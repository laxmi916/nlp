Multimodal Transformers + LLM Evaluation

Modern AI systems are not limited to text. Multimodal Transformers can process multiple types of information such as text and images and learn relationships between them.

This section covers two important areas:

  • Multimodal Transformers — working with text and images.
  • LLM Evaluation — measuring answer quality and identifying hallucinations.

Part A — Multimodal Transformers

1. What is a Multimodal Transformer?

A multimodal Transformer processes information from more than one modality, such as text, images, audio, or video. 

Text ──────┐
           │
           ▼
      Multimodal Model
           │
Image ─────┘
           │
           ▼
    Joint Representation
           │
           ▼
       Output

For example, a vision-language model can receive an image and a question: 

Image:
[photo of a dog]

Question:
"What animal is shown?"

                ↓

        Vision-Language Model

                ↓

             "Dog"

2. Text + Image Tasks

Common multimodal tasks include:

  • Image captioning
  • Visual question answering
  • Image-text similarity
  • Image classification
  • Document understanding
  • Visual reasoning

3. Example — Image Captioning

Image captioning generates a natural-language description of an image. 

Image
  ↓
Vision Encoder
  ↓
Visual Representation
  ↓
Language Decoder
  ↓
Text Caption

Install the required libraries:

pip install torch transformers pillow

Download or place an image named image.jpg in the same directory as the Python program. 


from transformers import (
    BlipProcessor,
    BlipForConditionalGeneration
)

from PIL import Image
import torch


# --------------------------------------------------
# 1. Load the image
# --------------------------------------------------

image = Image.open(
    "image.jpg"
).convert("RGB")


# --------------------------------------------------
# 2. Load the pretrained multimodal model
# --------------------------------------------------

model_name = (
    "Salesforce/blip-image-captioning-base"
)

processor = BlipProcessor.from_pretrained(
    model_name
)

model = BlipForConditionalGeneration.from_pretrained(
    model_name
)

model.eval()


# --------------------------------------------------
# 3. Prepare image
# --------------------------------------------------

inputs = processor(
    images=image,
    return_tensors="pt"
)


# --------------------------------------------------
# 4. Generate caption
# --------------------------------------------------

with torch.no_grad():

    output_ids = model.generate(
        **inputs,
        max_new_tokens=30
    )


# --------------------------------------------------
# 5. Convert tokens to text
# --------------------------------------------------

caption = processor.decode(
    output_ids[0],
    skip_special_tokens=True
)


# --------------------------------------------------
# 6. Display result
# --------------------------------------------------

print("Generated Caption:")
print(caption)

The important pipeline is: 

Image
 ↓
BLIP Vision Encoder
 ↓
Multimodal Representation
 ↓
Text Generation
 ↓
Caption

4. Example — Image + Text Classification with CLIP

CLIP learns a shared representation for images and text. It can compare an image with several text descriptions and determine which description is most compatible with the image. 

Image
  │
  ├───────────────┐
  │               │
Image Encoder   Text Encoder
  │               │
  ▼               ▼
Image Vector    Text Vectors
  │               │
  └───────┬───────┘
          ↓
     Similarity
          ↓
   Best matching text

Install:

pip install torch transformers pillow


from transformers import (
    CLIPProcessor,
    CLIPModel
)

from PIL import Image
import torch


# --------------------------------------------------
# 1. Load image
# --------------------------------------------------

image = Image.open(
    "image.jpg"
).convert("RGB")


# --------------------------------------------------
# 2. Candidate descriptions
# --------------------------------------------------

labels = [
    "a photo of a dog",
    "a photo of a cat",
    "a photo of a car",
    "a photo of a person"
]


# --------------------------------------------------
# 3. Load CLIP
# --------------------------------------------------

model_name = "openai/clip-vit-base-patch32"

processor = CLIPProcessor.from_pretrained(
    model_name
)

model = CLIPModel.from_pretrained(
    model_name
)

model.eval()


# --------------------------------------------------
# 4. Prepare image and text
# --------------------------------------------------

inputs = processor(
    text=labels,
    images=image,
    return_tensors="pt",
    padding=True
)


# --------------------------------------------------
# 5. Calculate image-text scores
# --------------------------------------------------

with torch.no_grad():

    outputs = model(**inputs)

    probabilities = outputs.logits_per_image.softmax(
        dim=1
    )


# --------------------------------------------------
# 6. Display scores
# --------------------------------------------------

for label, probability in zip(
    labels,
    probabilities[0]
):

    print(
        label,
        "->",
        probability.item()
    )


# --------------------------------------------------
# 7. Find best matching label
# --------------------------------------------------

best_index = probabilities[0].argmax().item()

print("\nBest match:")
print(labels[best_index])

This demonstrates a fundamental multimodal idea: represent different modalities in a comparable vector space.

Part B — LLM Evaluation

6. Why Evaluate an LLM?

A language model can produce fluent and convincing text without necessarily being correct. Therefore, evaluating only whether the answer "sounds good" is insufficient.

We may evaluate:

  • Correctness
  • Relevance
  • Faithfulness to provided context
  • Factual consistency
  • Instruction following
  • Safety
  • Hallucination rate

7. What is Hallucination?

A hallucination occurs when a model generates information that is unsupported, fabricated, or inconsistent with the available evidence. 

Question
   ↓
LLM
   ↓
Plausible-sounding answer
   ↓
Unsupported information
   ↓
Hallucination

For example: 

Context:
"Python was created by Guido van Rossum."

Question:
"Who created Python?"

Good answer:
"Guido van Rossum."

Hallucinated answer:
"Python was created by James Smith in 1985."

The second answer contains a factual claim that is not supported by the given context.

8. Hallucination in RAG

RAG reduces dependence on the model's internal knowledge by supplying retrieved context, but retrieval alone does not guarantee a correct answer. The model can still generate unsupported statements. 

Retrieved Context
       ↓
       LLM
       ↓
Generated Answer
       ↓
Is every important claim
supported by the context?
       ↓
Yes ──────── No
 ↓             ↓
Faithful    Possible
Answer      Hallucination

10. Exact Match Evaluation

For questions with short, well-defined answers, we can use Exact Match (EM). 

Exact Match =
Number of correct answers
──────────────────────────
Total answers


def exact_match(
    expected,
    generated
):

    return (
        expected.strip().lower()
        ==
        generated.strip().lower()
    )


evaluation_data = [

    {
        "expected": "4",
        "generated": "4"
    },

    {
        "expected": "Paris",
        "generated": "Paris"
    },

    {
        "expected": "Guido van Rossum",
        "generated": "Guido van Rossum"
    },

    {
        "expected": "RAG",
        "generated": "RAG system"
    }
]


correct = 0


for item in evaluation_data:

    if exact_match(
        item["expected"],
        item["generated"]
    ):

        correct += 1


accuracy = (
    correct / len(evaluation_data)
)


print(
    "Exact Match Accuracy:",
    accuracy
)

Exact Match is useful for short factual answers, but it is too strict for many natural-language generation tasks.

11. Text Similarity Evaluation

For generated text, we may compare the generated answer with a reference answer using metrics such as ROUGE or BLEU. These metrics measure different forms of textual overlap and should not be treated as complete measures of factual correctness.

Install:

pip install rouge-score


from rouge_score import rouge_scorer


reference = (
    "Python is a programming language."
)

generated = (
    "Python is a popular programming language."
)


scorer = rouge_scorer.RougeScorer(
    ["rouge1", "rougeL"],
    use_stemmer=True
)


scores = scorer.score(
    reference,
    generated
)


print("ROUGE-1 F1:")
print(
    scores["rouge1"].fmeasure
)


print("\nROUGE-L F1:")
print(
    scores["rougeL"].fmeasure
)

12. Why ROUGE Alone Is Not Enough

Reference:
"Paris is the capital of France."

Generated:
"Paris is the capital of Germany."

The generated answer shares many words with the reference, so lexical overlap metrics can still be relatively high even though the answer contains an important factual error.

Therefore: 

Good Evaluation
      =
Text Similarity
      +
Factual Correctness
      +
Relevance
      +
Instruction Following

13. Basic Hallucination Check Using Context

For a simple educational example, we can check whether important words or facts from a generated answer are supported by the supplied context. This is only a basic demonstration; real hallucination evaluation requires more sophisticated methods. 


context = """
Python was created by Guido van Rossum.
Python was first released in 1991.
"""


answer_good = (
    "Python was created by Guido van Rossum."
)

answer_bad = (
    "Python was created by James Smith in 1985."
)


def basic_support_check(
    context,
    answer
):

    answer_words = set(
        answer.lower().replace(
            ".", ""
        ).split()
    )

    context_words = set(
        context.lower().replace(
            ".", ""
        ).split()
    )

    common_words = (
        answer_words & context_words
    )

    coverage = (
        len(common_words)
        /
        len(answer_words)
    )

    return coverage


print(
    "Good answer coverage:",
    basic_support_check(
        context,
        answer_good
    )
)


print(
    "Bad answer coverage:",
    basic_support_check(
        context,
        answer_bad
    )
)

This illustrates the idea of checking generated text against retrieved evidence, but word overlap is not a reliable hallucination detector. A factual claim can use different words from the evidence and still be correct.

14. A Better Evaluation Framework

For practical LLM applications, evaluate multiple dimensions instead of using one metric.

Metric / Dimension What it measures
Exact Match Whether the answer exactly matches the expected answer.
ROUGE / BLEU Textual overlap with reference text.
Semantic Similarity Similarity in meaning between generated and reference answers.
Factual Correctness Whether claims are factually correct.
Faithfulness Whether the answer is supported by supplied context.
Relevance Whether the answer addresses the question.
Instruction Following Whether the model follows the requested format or constraints.

16. Multimodal Evaluation

Multimodal systems also need to be evaluated for whether their answers are actually supported by the image. 

Image
  ↓
Vision-Language Model
  ↓
Generated Description
  ↓
Compare with Image / Reference
  ↓
Correct?
  ↓
Yes / No

For example, if an image contains a dog but the model says "a cat", the answer is visually incorrect even if the generated sentence is grammatically perfect.

17. Multimodal Hallucination

A vision-language model can also hallucinate objects, attributes, or events that are not present in the image. 

Image:
A dog sitting on grass

Model:
"A brown dog is sitting on grass
beside a red car."

If there is no red car in the image, the additional claim is unsupported. 

Visual Evidence
      ↓
Generated Claims
      ↓
Compare Claims with Evidence
      ↓
Supported / Unsupported

18. Important Evaluation Principle

A language model can produce an answer that is fluent, relevant-looking, and semantically similar to a reference while still being factually wrong. Therefore, no single automatic metric completely evaluates an LLM or multimodal model. 

LLM Evaluation
      ↓
 ┌────┼─────────┬──────────┐
 ↓    ↓         ↓          ↓
Accuracy  Relevance  Faithfulness  Safety
      ↓
Overall Evaluation
