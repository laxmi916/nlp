AI Agents with Python

1. What is an AI Agent?

A normal question-answering application usually follows a fixed sequence: receive a question, retrieve information if needed, and generate an answer. An AI Agent can do more. It interprets the user's request, decides whether a tool is needed, asks to use the appropriate tool, receives the tool's result, and then prepares a response.

For example, consider an e-commerce assistant. A customer may ask about the return policy, calculate a discount, or ask a question that requires both operations.

Simple definition: An AI Agent is an application in which an AI model can decide when to use available tools to complete a task. The model decides which tool to request; Python executes the actual function.

RAG application vs AI Agent

RAG question-answeringAI Agent
Retrieves relevant information and uses it to answer.Can choose among tools based on the user's request.
Usually follows a predefined retrieval-and-generation flow.Can follow different tool-use paths for different requests.

An agent can use a RAG function as one of its tools. In this tutorial, the knowledge-base search tool reuses the RAG pipeline, while a second tool performs a discount calculation.

2. Understand the Agent workflow

The notebook implements the following interaction between the customer, Gemini and Python tools:

1. RequestCustomer asks
2. DecideGemini selects a tool
3. CallStructured function call
4. ExecutePython runs function
5. ReturnTool result to Gemini
6. AnswerGemini responds
  1. The customer enters a request.
  2. Gemini interprets the request and decides whether a tool is needed.
  3. If a tool is needed, Gemini returns a structured function call with its name and arguments.
  4. Python executes the requested function.
  5. The tool result is sent back to Gemini.
  6. Gemini produces a natural-language response for the customer.
Important distinction: Gemini does not directly execute our Python code. It requests a function call. Our Python application checks the requested function, runs it, and sends the result back to Gemini.

5. Prepare the RAG knowledge base

Before the agent can search store policies, we need to index the policy documents. This is the RAG part of the application.

Initialize persistent ChromaDB

chroma_client = chromadb.PersistentClient(
    path="/content/chroma_db"
)

collection = chroma_client.get_or_create_collection(
    name="store_knowledge"
)

Unlike a temporary in-memory client, PersistentClient stores ChromaDB data at the specified path. In this Colab example, the path is /content/chroma_db.

Read and split documents into chunks

def read_documents(folder):
    loaded_documents = []

    for file_path in Path(folder).glob("*.txt"):
        text = file_path.read_text(encoding="utf-8")
        loaded_documents.append({
            "filename": file_path.name,
            "text": text
        })

    return loaded_documents


def split_text(text, chunk_size=700, overlap=100):
    chunks = []
    start = 0

    while start < len(text):
        end = start + chunk_size
        chunks.append(text[start:end])

        if end >= len(text):
            break

        start = end - overlap

    return chunks

read_documents() reads every text file in the folder. split_text() divides long text into chunks of up to 700 characters. The next chunk starts 100 characters before the previous chunk ends, creating an overlap.

Why overlap? A useful sentence or idea may fall across a chunk boundary. Overlap keeps some surrounding text in the next chunk, reducing the chance of separating related information.

Generate embeddings

def create_embedding(text):
    result = client.models.embed_content(
        model=EMBEDDING_MODEL,
        contents=text
    )

    return result.embeddings[0].values

This function sends a text chunk to gemini-embedding-001 and returns its numerical vector.

Index the chunks in ChromaDB

def ingest_documents():
    loaded_documents = read_documents("documents")

    ids = []
    texts = []
    embeddings = []
    metadatas = []

    for document in loaded_documents:
        chunks = split_text(document["text"])

        for index, chunk in enumerate(chunks):
            ids.append(f'{document["filename"]}_{index}')
            texts.append(chunk)
            embeddings.append(create_embedding(chunk))

            metadatas.append({
                "source": document["filename"],
                "chunk": index
            })

    if ids:
        collection.upsert(
            ids=ids,
            documents=texts,
            embeddings=embeddings,
            metadatas=metadatas
        )

    print(f"Indexed {len(ids)} document chunks.")


ingest_documents()
print("Records in collection:", collection.count())

For every chunk, the program creates an ID, generates an embedding, and records metadata containing the source filename and chunk number. upsert() inserts or updates these records in ChromaDB.

6. Create the document retrieval function

When a customer asks a policy question, we convert that question into an embedding and retrieve the three most relevant chunks.

def retrieve_documents(question, top_k=3):
    if collection.count() == 0:
        return []

    query_vector = create_embedding(question)

    results = collection.query(
        query_embeddings=[query_vector],
        n_results=min(top_k, collection.count()),
        include=["documents", "metadatas", "distances"]
    )

    documents = results.get("documents", [[]])[0]
    metadatas = results.get("metadatas", [[]])[0]

    retrieved = []

    for document, metadata in zip(documents, metadatas):
        retrieved.append({
            "text": document,
            "source": metadata.get("source", "unknown")
        })

    return retrieved

The function returns the retrieved text along with its source filename. The distance values are requested from ChromaDB, although this function does not use them in its return value.

7. Build the RAG question-answering function

We can now use the retrieval function to create a normal RAG question-answering function. This helps us understand the component that will later become an Agent tool.

def answer_question(question):
    retrieved = retrieve_documents(question)

    if not retrieved:
        return (
            "I could not find relevant information "
            "in the store documents."
        )

    context_parts = []

    for item in retrieved:
        context_parts.append(
            f'Source: {item["source"]}\n{item["text"]}'
        )

    context = "\n\n".join(context_parts)

    prompt = f"""
Answer the question using only the store policy context below.
If the answer is not present in the context, clearly say that
the documents do not provide the information.

Context:
{context}

Question:
{question}
"""

    response = client.models.generate_content(
        model=GENERATION_MODEL,
        contents=prompt
    )

    return response.text or "No text response was returned."


print(answer_question(
    "When is free standard shipping available?"
))

This function follows a fixed RAG process: retrieve relevant policy text, add it to a prompt, and ask Gemini to generate an answer.

In the Agent, we will expose the retrieval operation as a tool. Gemini will decide when to call it rather than our program calling it for every question.

8. Create Python tools for the Agent

A tool is a normal Python function that performs a specific task. In this example, we provide two tools.

Tool 1 — Search the knowledge base

def search_knowledge_base(question: str) -> str:
    """Search store policy documents for relevant information."""

    results = retrieve_documents(question, top_k=3)

    if not results:
        return (
            "No relevant information was found "
            "in the store documents."
        )

    passages = []

    for index, item in enumerate(results, start=1):
        passages.append(
            f'Passage {index} (source: {item["source"]}): '
            f'{item["text"]}'
        )

    return "\n\n".join(passages)

This function reuses the RAG retrieval pipeline. It returns the matching passages and their source filenames as a text result.

Tool 2 — Calculate a discount

def calculate_discount(
    price: float,
    discount_percent: float
) -> str:
    """Calculate the final price after a percentage discount."""

    if price < 0:
        return "Price cannot be negative."

    if discount_percent < 0 or discount_percent > 100:
        return "Discount must be between 0 and 100."

    discount_amount = price * discount_percent / 100
    final_price = price - discount_amount

    return (
        f"Original price: Rs. {price:.2f}. "
        f"Discount: {discount_percent:.2f}%. "
        f"Discount amount: Rs. {discount_amount:.2f}. "
        f"Final price: Rs. {final_price:.2f}."
    )


print(calculate_discount(5000, 10))
print(search_knowledge_base("What is the express delivery time?"))

This function validates the inputs, calculates the discount amount, subtracts it from the original price, and returns a formatted result.

Why are these called tools? They give the Agent capabilities beyond generating text. One tool searches external knowledge stored in ChromaDB; the other performs a deterministic calculation using Python.

9. Tell Gemini which tools are available

Defining Python functions is not enough. Gemini also needs descriptions of the available functions, their names, and the arguments they accept. We provide this information through function declarations.

Function declaration for knowledge search

search_function = types.FunctionDeclaration(
    name="search_knowledge_base",
    description=(
        "Search the store policy documents for "
        "an answer to a policy question."
    ),
    parameters_json_schema={
        "type": "object",
        "properties": {
            "question": {
                "type": "string",
                "description": "The store policy question to search for."
            }
        },
        "required": ["question"]
    }
)

Function declaration for discount calculation

discount_function = types.FunctionDeclaration(
    name="calculate_discount",
    description=(
        "Calculate the final price after "
        "a percentage discount."
    ),
    parameters_json_schema={
        "type": "object",
        "properties": {
            "price": {
                "type": "number",
                "description": "Original product price in rupees."
            },
            "discount_percent": {
                "type": "number",
                "description": "Discount percentage from 0 to 100."
            }
        },
        "required": ["price", "discount_percent"]
    }
)

The declaration describes what the tool does and what input parameters are required. Gemini uses these descriptions to decide which function is appropriate and to prepare the arguments.

Group the function declarations into a tool

agent_tools = types.Tool(
    function_declarations=[
        search_function,
        discount_function
    ]
)

We now have one tool configuration containing both available functions.

10. Implement the AI Agent

This is the main part of the tutorial. The run_agent() function sends the customer's request to Gemini along with the tool descriptions. It then handles any function calls returned by the model.

Step A — Give the Agent instructions

system_instruction = """
You are a helpful assistant for a demonstration e-commerce store.

Use search_knowledge_base for questions about store policies,
returns, refunds, shipping, delivery, or tracking information.

Use calculate_discount for percentage discount calculations.

Do not invent store policy information. If the documents do not
contain the answer, say that the documents do not provide it.

For greetings or general conversation, answer directly.
Explain tool results clearly.
"""

These instructions guide the Agent's behavior and explain when each tool should be used.

Step B — Create the conversation

conversation = [
    types.Content(
        role="user",
        parts=[types.Part.from_text(text=user_question)]
    )
]

The conversation begins with the customer's question. We will add Gemini's responses and the tool results as the interaction continues.

Step C — Ask Gemini to decide what to do

response = client.models.generate_content(
    model=GENERATION_MODEL,
    contents=conversation,
    config=types.GenerateContentConfig(
        system_instruction=system_instruction,
        tools=[agent_tools],
        automatic_function_calling=(
            types.AutomaticFunctionCallingConfig(disable=True)
        )
    )
)

We pass the system instructions and tool declarations to Gemini. Automatic function calling is disabled because this notebook demonstrates the tool-calling process manually in Python.

Gemini may return a normal text answer, or it may return a structured function call asking our application to execute a tool.

Step D — Inspect the model response

model_content = response.candidates[0].content
conversation.append(model_content)

function_calls = [
    part.function_call
    for part in model_content.parts
    if part.function_call is not None
]

if not function_calls:
    return response.text or "The model did not return a text answer."

We add Gemini's response to the conversation and inspect its parts for function calls. If no function call is present, we return the model's text answer.

Step E — Execute the requested Python function

tool_response_parts = []

for function_call in function_calls:
    tool_name = function_call.name
    arguments = dict(function_call.args or {})

    try:
        if tool_name == "search_knowledge_base":
            result = search_knowledge_base(
                question=arguments["question"]
            )

        elif tool_name == "calculate_discount":
            result = calculate_discount(
                price=float(arguments["price"]),
                discount_percent=float(
                    arguments["discount_percent"]
                )
            )

        else:
            result = f"Unknown tool: {tool_name}"

        tool_result = {"result": result}

    except Exception as error:
        tool_result = {"error": str(error)}

    print(f"Tool called: {tool_name}")
    print("Tool result:", tool_result)

    tool_response_parts.append(
        types.Part.from_function_response(
            name=tool_name,
            response=tool_result
        )
    )

For every requested function call, Python reads the function name and arguments. It then executes the matching local function and stores the result in a function-response part.

Important: Never execute arbitrary function names or code supplied by a model. This example explicitly checks the requested name against the two functions that the application allows.

Step F — Send the tool result back to Gemini

conversation.append(
    types.Content(
        role="tool",
        parts=tool_response_parts
    )
)

The tool result is added to the conversation. Gemini can now use that result to prepare a response for the customer. If it requests another tool, the application can execute that call in the next round.

Complete Agent function

The following combines the steps above. The loop allows up to five tool-calling rounds.

def run_agent(user_question):
    system_instruction = """
You are a helpful assistant for a demonstration e-commerce store.

Use search_knowledge_base for questions about store policies,
returns, refunds, shipping, delivery, or tracking information.

Use calculate_discount for percentage discount calculations.

Do not invent store policy information. If the documents do not
contain the answer, say that the documents do not provide it.

For greetings or general conversation, answer directly.
Explain tool results clearly.
"""

    conversation = [
        types.Content(
            role="user",
            parts=[types.Part.from_text(text=user_question)]
        )
    ]

    for step in range(5):
        response = client.models.generate_content(
            model=GENERATION_MODEL,
            contents=conversation,
            config=types.GenerateContentConfig(
                system_instruction=system_instruction,
                tools=[agent_tools],
                automatic_function_calling=(
                    types.AutomaticFunctionCallingConfig(
                        disable=True
                    )
                )
            )
        )

        model_content = response.candidates[0].content
        conversation.append(model_content)

        function_calls = [
            part.function_call
            for part in model_content.parts
            if part.function_call is not None
        ]

        if not function_calls:
            return (
                response.text
                or "The model did not return a text answer."
            )

        tool_response_parts = []

        for function_call in function_calls:
            tool_name = function_call.name
            arguments = dict(function_call.args or {})

            try:
                if tool_name == "search_knowledge_base":
                    result = search_knowledge_base(
                        question=arguments["question"]
                    )

                elif tool_name == "calculate_discount":
                    result = calculate_discount(
                        price=float(arguments["price"]),
                        discount_percent=float(
                            arguments["discount_percent"]
                        )
                    )

                else:
                    result = f"Unknown tool: {tool_name}"

                tool_result = {"result": result}

            except Exception as error:
                tool_result = {"error": str(error)}

            print(f"Tool called: {tool_name}")
            print("Tool result:", tool_result)

            tool_response_parts.append(
                types.Part.from_function_response(
                    name=tool_name,
                    response=tool_result
                )
            )

        conversation.append(
            types.Content(
                role="tool",
                parts=tool_response_parts
            )
        )

    return (
        "The Agent reached the maximum number "
        "of tool-calling rounds."
    )

12. RAG vs AI Agent — final understanding

In this implementation, RAG and AI Agents work together, but they have different responsibilities.

ComponentResponsibility
Gemini embedding modelConverts policy chunks and customer questions into vectors.
ChromaDBStores vectors and retrieves relevant policy chunks.
search_knowledge_baseConnects the Agent to the RAG retrieval function.
calculate_discountPerforms a calculation using Python.
Gemini 2.5 FlashInterprets the request, selects tools when needed, and generates the response.
run_agent()Coordinates the model, tool execution and tool-result exchange.

Important production considerations

  • The policy files in this notebook contain demonstration information only.
  • A production e-commerce assistant should connect to verified product, inventory, order, payment and customer systems.
  • It must authenticate customers and authorize access before exposing private order information or performing transactions.
  • Tool inputs must be validated, and sensitive actions should have suitable permission checks and confirmation steps.
  • Tool errors, missing information and maximum tool-call rounds should be handled clearly.

In summary: An AI Agent uses an LLM to interpret a request and decide which available tool can help. The application executes the tool and returns its result to the model. The model then uses the result to produce a response. In this tutorial, we built an e-commerce demonstration Agent with two tools: a RAG-based policy search and a Python discount calculator.
